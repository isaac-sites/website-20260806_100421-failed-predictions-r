## Introduction

A UFO prediction cannot be evaluated fairly unless there is trustworthy evidence showing exactly what was claimed before the predicted date arrived. Without that safeguard, failed forecasts can be rewritten after the fact by changing dates, locations, wording or success criteria. Preregistration addresses this problem by creating a time-stamped, read-only record of a prediction before the outcome is known. Although the practice originated in scientific research, the same principle applies to extraordinary public claims: once the original wording is fixed, later observers can compare what actually happened with what was originally promised rather than with a revised version. This makes failed UFO predictions easier to identify and prevents hindsight from turning an incorrect forecast into an apparent success.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://help.osf.io/article/330-welcome-to-registrations" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: help.osf.io">[OSF Support]</a><span class="citation-popover" role="note"><span class="citation-popover-source">help.osf.io</span><span class="citation-popover-title">Support Welcome to Registrations &amp; Preregistrations!</span><span class="citation-popover-snippet">OSF SupportWelcome to Registrations &amp; Preregistrations! - OSF SupportJuly 17, 2026...</span><span class="citation-popover-meta">Published: July 17, 2026</span></span></span>

## Can a UFO Prediction Be Proved in Advance?

A prediction becomes substantially more testable when its contents are permanently recorded before the deadline. The goal is not to prove that a prediction is true in advance, but to prove that the prediction itself existed in a specific form before anyone knew the outcome.

This distinction matters because hindsight bias is a well-documented cognitive tendency. Once events have occurred, people often remember earlier expectations as being more accurate or more specific than they really were. A durable preregistration allows readers to compare the original statement with later claims instead of relying on memory or retrospective interpretation.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://openscience.cuni.cz/OSCIEN-160.html" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: openscience.cuni.cz">[Centrum pro podporu open science]</a><span class="citation-popover" role="note"><span class="citation-popover-source">openscience.cuni.cz</span><span class="citation-popover-title">Centrum pro podporu open science Preregistration</span><span class="citation-popover-snippet">Centrum pro podporu open sciencePreregistration - Open Science Support Centre...</span></span></span>

In the context of failed UFO predictions, preregistration also separates genuine forecasting from post-event storytelling. If someone later claims, "I always said the landing would happen in this region during this period," the archived record either supports or contradicts that assertion.

## What a Pre-Deadline Record Must Preserve

A useful preregistration should preserve the complete prediction rather than only its broad theme. At a minimum, the record should include:

* The [exact wording]({{ 'exact-wording/' | relative_url }}) of the prediction.

<div class="content-enhancement content-enhancement--insight-grid" markdown="1">

* The date and time it was recorded.
* The deadline by which the prediction should occur.
* The location or geographical scope, if relevant.
* The observable event that is expected.
* The evidence that will count as confirmation.
* Any conditions that would count as failure.

</div>

The record should remain readable after publication and should not permit silent editing. If changes become necessary—for example, correcting a typographical error—they should be recorded transparently so readers can distinguish the original claim from later amendments. This mirrors established preregistration practice in open research, where the initial plan remains preserved even if later updates are documented separately.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://help.osf.io/article/330-welcome-to-registrations" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: help.osf.io">[OSF Support]</a><span class="citation-popover" role="note"><span class="citation-popover-source">help.osf.io</span><span class="citation-popover-title">Support Welcome to Registrations &amp; Preregistrations!</span><span class="citation-popover-snippet">OSF SupportWelcome to Registrations &amp; Preregistrations! - OSF SupportJuly 17, 2026...</span><span class="citation-popover-meta">Published: July 17, 2026</span></span></span>

## How Preregistration Blocks Hindsight Editing

The greatest value of preregistration is that it limits opportunities to redefine success after the outcome is known.

Without a fixed record, a failed UFO prediction can be altered in several familiar ways:

* **Moving the deadline.** A missed prediction becomes "slightly delayed."
* **Changing the location.** A promised event shifts from one city or country to another.
* **Reducing [specificity]({{ 'specificity/' | relative_url }}).** A predicted public landing becomes a vague increase in sightings.
* **Changing the required evidence.** Public observation becomes private [revelation]({{ 'revelation/' | relative_url }}) or symbolic fulfilment.
* **Claiming hidden success.** An event supposedly occurred but was concealed from public knowledge.

Because the original prediction remains accessible, readers can compare every later explanation against the initial commitment. If the prediction stated that a large craft would remain visible over a named city on a specified date, then the absence of that event constitutes a straightforward failure. Replacing it afterwards with a different location or different type of encounter becomes visibly inconsistent with the archived record rather than an unnoticed revision.

Importantly, preregistration does not prevent someone from issuing an updated prediction. It simply requires that the revision be treated as a new forecast rather than a reinterpretation of the old one.

## Practical Ways to Create a Durable Public Record

A preregistration system does not need specialised UFO infrastructure. What matters is that the record is independently time-stamped and resistant to unnoticed alteration.

Common approaches include:


<div class="content-enhancement content-enhancement--insight-grid" markdown="1">

* Public repositories that create immutable, time-stamped registrations.<span class="citation-chip-wrap"><a class="citation-chip" href="https://researchdata.unibas.ch/en/planning/preregistration/" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: researchdata.unibas.ch">[researchdata.unibas.ch]</a><span class="citation-popover" role="note"><span class="citation-popover-source">researchdata.unibas.ch</span><span class="citation-popover-snippet">Source details in endnotes.</span></span></span>
* Trusted digital archives that preserve original uploads.
* Forecasting platforms with fixed opening, closing and resolution dates.
* Publicly accessible documents whose revision history cannot erase the original version.

</div>

Modern forecasting platforms illustrate this principle through governance rather than belief. They distinguish when predictions open, when forecasting closes, and when questions are resolved, while discouraging substantive edits once forecasting has begun because such changes would unfairly alter the commitment participants originally evaluated.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://www.metaculus.com/faq/" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: metaculus.com">[Metaculus]</a><span class="citation-popover" role="note"><span class="citation-popover-source">metaculus.com</span><span class="citation-popover-snippet">Metaculus FAQ...</span></span></span>

Even a simple signed document published before the deadline is stronger evidence than an undated claim remembered only after the event.

## What Preregistration Does Not Guarantee

Preregistration increases accountability, but it does not make a prediction correct.

A precisely archived UFO prediction may still fail completely. Conversely, an ambiguous prediction does not become more accurate merely because it was time-stamped. The archive preserves the original commitment; it does not validate its content.

Likewise, preregistration cannot eliminate disputes over evidence if the prediction itself uses vague language. A statement such as "humanity will experience greater extraterrestrial awareness before year's end" remains difficult to evaluate because the claimed outcome lacks clear operational definitions. A permanent record prevents later rewriting, but it cannot compensate for an imprecise prediction.

## Why This Matters for Failed UFO Predictions

Many historical UFO prophecies have survived repeated failures because supporters were able to reinterpret them after the predicted dates passed. Deadlines were extended, meanings broadened, or originally concrete claims were reframed as symbolic events. Without an independently verifiable record of the original wording, later audiences may struggle to distinguish genuine fulfilment from retrospective reinterpretation.

Preregistration changes the standard of evaluation. Instead of asking what believers now say was predicted, investigators can ask a simpler question: *What was actually recorded before the deadline?* If the archived prediction and the observed outcome do not match, the prediction has failed under the conditions originally stated.

For that reason, preregistration is an important practical companion to [falsifiability]({{ 'falsifiability/' | relative_url }}). A prediction that can be tested must first be preserved exactly as it was made; otherwise, hindsight editing can continually move the target and make clear failures appear uncertain.<span class="citation-link-wrap"><a class="citation-inline-link" href="https://help.osf.io/article/330-welcome-to-registrations" target="_blank" rel="noopener noreferrer nofollow" aria-label="View source: help.osf.io">[osf.io]</a><span class="citation-popover" role="note"><span class="citation-popover-source">help.osf.io</span><span class="citation-popover-title">Support Welcome to Registrations &amp; Preregistrations!</span><span class="citation-popover-snippet">OSF SupportWelcome to Registrations &amp; Preregistrations! - OSF SupportJuly 17, 2026...</span><span class="citation-popover-meta">Published: July 17, 2026</span></span></span>

  function encodeQuery(value) {
    return encodeURIComponent(String(value || '').replace(/\s+/g, ' ').trim()).replace(/%20/g, '+');

  function buildUrl(query, reference, marketId) {
    var cfg = markets[marketId] || markets[defaultMarket];
    if (!cfg) return '#';
    var template = String(cfg.url_template || 'https://www.ebay.com/sch/i.html?_nkw={query}');

    var params = [];

    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-selected-market-label]')).forEach(function (label) {
      label.textContent = selectedText;
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-selected-market-flag], [data-ebay-trigger-market-flag]')).forEach(function (flag) {
      flag.className = flagClass(marketId);
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-trigger-market-label]')).forEach(function (label) {
      label.textContent = selectedText;
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-domain-label]')).forEach(function (label) {
      label.textContent = domainLabel(marketId);
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-market-option]')).forEach(function (button) {
      button.setAttribute('aria-selected', button.getAttribute('data-ebay-market-option') === marketId ? 'true' : 'false');
    });
    Array.prototype.slice.call(section.querySelectorAll('[data-ebay-market-button]')).forEach(function (button) {
      var active = button.getAttribute('data-ebay-market-button') === marketId;
      button.setAttribute('aria-pressed', active ? 'true' : 'false');
    });
    section.setAttribute('data-ebay-selected-market', marketId);
    if (persist) {
      try { if (window.localStorage) localStorage.setItem('phoenix-ebay-market', marketId); } catch (err) {}
    }
    closeMenu(section);
  }

        });
      });
      document.addEventListener('click', function () { closeMenu(section); });
    }

      button.addEventListener('click', function () {
        applyMarket(section, button.getAttribute('data-ebay-market-button'), true);
      });
